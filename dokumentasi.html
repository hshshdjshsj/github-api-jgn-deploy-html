Request & Central Security

Lapisan pertama yang dilewati request sebelum business handler. Proses 1.1

Request Entry, Origin & Contract

Request tidak langsung diarahkan ke fungsi bisnis. Backend terlebih dahulu membentuk konteks request, menentukan action yang diminta, membatasi method dan ukuran body, memeriksa CORS/origin untuk jalur browser, dan memvalidasi kontrak field. Kelompok 7

S2S Internal Server Mesh

Internal role-to-role traffic is not treated like a trusted LAN shortcut. Source defines a seven-signature S2S policy where all seven asymmetric signatures must be present and valid before the business handler. Registry, replay protection, revocation, and attributed failures are persisted in the dedicated security database. Role mesh egress is also allowlisted so a server cannot freely call arbitrary destinations/actions.

Kelompok 9

Lost Passkey Recovery / S-RECO

Lost-passkey recovery is a separate high-assurance flow. Public HTML first validates the recovery link and obtains a signed encrypted vault. The client verifies Ed25519 AND ML-DSA-87, strict manifest/anti-downgrade policy, fixed Argon2id profile, vault hashes and transport suite. User factors are used locally to unwrap/decrypt recovery material, then an online hybrid envelope is submitted for server verification. Dedicated recovery compute is isolated by role/environment and uses X25519 + ML-KEM-1024 + HKDF-SHA512 + AES-256-GCM transport.

Proses 10.5

Security Incident, Ban & Notification

Security incident handling stores only safe identity fingerprints/reason metadata needed to enforce bans or investigate. Logout remains allowed so browser cookies can still be cleared even when an identity is blocked.
